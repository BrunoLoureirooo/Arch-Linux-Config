# Baseline and spike findings (2026-10-23)

Recorded by unit U0 (test rig and spikes). All "verified in rig" values come from a
headless nested Hyprland started with `tests/rig/nested-hypr.sh`. The live session was
never queried with `hyprctl` and nothing under `~/.config` was changed.

## Test rig in one paragraph

`tests/rig/setup-testbin.sh` fetches quickshell 0.3.1, matugen 4.2.0, wev, wtype, labwc
(plus missing deps libdwarf, cpptrace, qt6-wayland, wlroots0.20, libliftoff, libsfdo)
from the Arch mirror (archive.archlinux.org fallback when the local sync db is older
than the mirror), xremap 0.15.15 (`xremap-linux-x86_64-hypr.zip`) and a static
shellcheck, all into `~/.cache/rice-testbin/`. Source `~/.cache/rice-testbin/env.sh`
to use them. `tests/rig/nested-hypr.sh start <config.lua>` runs Hyprland 0.56.2 as a
Wayland client of a private labwc that uses only the wlroots headless backend, so
nothing appears on a real screen; the test outputs are Hyprland headless outputs `DP-1`
and `eDP-1` (1920x1080). Every rig command goes through `tests/rig/rig_env.sh`, which
refuses the live signature. `tests/rig/selftest.sh` checks the whole rig end to end.

Why labwc: Aquamarine 0.15.1 cannot start with only its headless backend (headless has
no DRM fd, so `CBackend::start` fails with "no allocator available"); Hyprland always
asks for headless + DRM + Wayland. DRM is out (it would open a seat session and GPU),
so the Wayland backend needs a parent compositor. Aquamarine binds `xdg_wm_base` v6;
cage 0.3.1 and sway 1.12 only offer v5 (cage was tried: `invalid version for global
xdg_wm_base (10): expected at most 5, got 6`), labwc 0.20.2 offers v6. There is no
`AQ_BACKENDS` variable in Aquamarine 0.15.1.

Isolation measures in `nested-hypr.sh`: `WAYLAND_DISPLAY`, `HYPRLAND_INSTANCE_SIGNATURE`,
`DISPLAY`, `NOTIFY_SOCKET`, `XDG_SESSION_ID` unset; `LIBSEAT_BACKEND=rig-no-seat` (no
seat session, so Aquamarine's DRM backend cannot open a card node, and Hyprland skips
its systemd/dbus activation-env update, which only runs with a session);
`HYPRLAND_NO_SD_VARS=1`, `HYPRLAND_NO_SD_NOTIFY=1`; `LABWC_UPDATE_ACTIVATION_ENV=false`;
`labwc -C ~/.cache/rice-testbin/labwc` (empty config dir, no autostart); scratch
`XDG_CONFIG_HOME/DATA/STATE/CACHE` under `~/.cache/rice-testbin/xdg/`. Every rig process
carries `RICE_RIG_ID=<token>`; `stop` kills only processes with that token.

## Drift check

**The live files do NOT match the repo.** The live config is ahead of the repo; the
migration must start from the live files, not from `dot_config/`.

`chezmoi -S "$PWD" diff ~/.config/hypr ~/.config/waybar ~/.config/wofi` printed nothing
(exit 0) when its output was not a terminal; with `--no-pager diff -r` it shows the
differences (`chezmoi status` agrees: `MM` on three files). In chezmoi's diff, `-` is
the live file and `+` is what `chezmoi apply` would write from the repo.

## Spike a: mouse side-button codes

- Physical side buttons: **unverified, expected 275 (BTN_SIDE) / 276 (BTN_EXTRA)**. They
  cannot be pressed unattended, and the rig has no pointer device (wtype is keyboard
  only; uinput would also reach the live compositor, so it was not used).
- Verified in rig: `hl.bind("mouse:275", hl.dsp.exec_cmd(...), { description = ... })`
  (no modifier, bare `mouse:275`) loads with no config error and is listed by
  `hyprctl -i <sig> binds -j` as
  `{'key': 'mouse:275', 'modmask': 0, 'mouse': False, 'dispatcher': '__lua', ...}`;
  same for `mouse:276`. (`mouse = true` in the options is only for drag/resize binds.)

## Spike b: Lua config

1. **`hyprland.lua` beats `hyprland.conf`** when both are in the config dir. Tested with
   a scratch `XDG_CONFIG_HOME` containing `hypr/hyprland.lua` (border 3) and
   `hypr/hyprland.conf` (border 9), Hyprland started with no `--config`
   (`nested-hypr.sh start <dir>`): `getoption general:border_size` = `int: 3`, log:
   `[cfg] Using lua config found at .../hypr/hyprland.lua`. (Hyprland 0.55+ deprecates
   hyprlang; the wiki documents only `hyprland.lua`.)
2. **`require("lib.pools")`** loads `lib/pools.lua` next to the config (relative to the
   directory of `hyprland.lua`; the wiki also allows `require("lib/pools")`). Verified:
   `hyprctl repl 'return require("lib.pools").name'` -> `pools-loaded`; `minimal.lua`
   uses `require("lib.rigbind")` the same way. Each `require` runs in its own protected
   scope (errors do not stop other files), but a missing module is a hard error in the
   caller; use `pcall(require, ...)` for optional modules. Raw Lua require: `__require`.
3. **Binds** (all verified to register in rig):
   - no-modifier mouse button: `hl.bind("mouse:275", <dispatcher|function>, opts)`
   - switch: `hl.bind("switch:on:Lid Switch", hl.dsp.exec_cmd("..."), { locked = true })`
     (also `switch:off:<name>` and `switch:<name>` for any toggle). Shows as key
     `switch:on:Lid Switch`, `locked: True`. Firing it is unverified (no switch device in rig).
   - Lua function bind: `hl.bind("SUPER + F10", function() ... end, opts)`; verified firing via keys.sh.
4. **Gradient border:** `hl.config({ general = { col = { active_border = { colors = {
   "rgba(ff0000ff)", "rgba(00ff00ff)" }, angle = 45 }, inactive_border = "rgba(595959aa)" } } })`.
   `hyprctl getoption general:col.active_border` -> `gradient data: ffff0000 ff00ff00 45deg`;
   visible red-to-green border on a kitty window in the rig screenshot.
5. **Workspace rule:** `hl.workspace_rule({ workspace = "3", monitor = "desc:<description>",
   persistent = true })`; add `default = true` to make it the monitor's start workspace.
   `hyprctl workspacerules` shows `monitor: desc:...`, `persistent: true`. A rule on
   `monitor = "eDP-1", persistent = true, default = true` made workspace 4 exist on eDP-1.
   Caveat: headless outputs have an empty `description`, so `desc:` matching cannot be
   exercised in the rig; the live BenQ description is `BNQ BenQ EX2510S K8M02386019`
   (from the live config, i.e. `desc:BNQ BenQ EX2510S K8M02386019`).
6. **Config check exists:** `Hyprland --verify-config --config <file.lua>` prints
   `======== Config parsing result:` then `config ok` (exit 0), or each error with
   file:line (exit 1; e.g. `broken.lua:1: error setting 'general.border_size': integer
   type requires a bool or an integer`, `broken.lua:2: attempt to call a nil value`).
   `require`d modules are resolved. Wrapped as `tests/rig/verify-config.sh <file>` (clean env).
7. **Triggering Lua from a test:** `hyprctl -i <sig> dispatch '<lua dispatcher expr>'`
   takes Lua, e.g. `hyprctl dispatch 'hl.dsp.exec_cmd("touch ...")'` (verified; the
   upstream example config itself uses `hyprctl dispatch 'hl.dsp.exit()'`).
   `hyprctl -i <sig> eval '<lua chunk>'` runs any Lua in the config state (verified with
   `os.execute`), and `hyprctl -i <sig> repl 'return <expr>'` prints a value. A bind's
   anonymous function cannot be called by name (`hyprctl binds` shows `dispatcher:
   __lua, arg: <n>`), so either expose the function in a module/global and `eval` it,
   or press the bind with `tests/rig/keys.sh` (verified: SUPER+F10 Lua-function bind fired).
   Also `hyprctl eval 'hl.bind(...)'` adds binds at runtime.

Rig gotcha found on the way: wtype uploads its own keymap, so with default settings
Hyprland resolves its keycodes through the configured layout and an `hl.bind` never
matches (wtype's F12 = keycode 9 = Escape in `us`). `keys.sh` sets
`input.resolve_binds_by_sym = true` at runtime before each call; with that, keys reach
both clients and binds.

  `hyprctl clients -j` -> `class: kitty`, `initialClass: kitty`, `xwayland: False`.
  `xremap --desktop hypr --list-windows` against the nested instance printed

  `hyprctl clients` before relying on them.

## Spike d: matugen JSON

Command that worked (private matugen 4.2.0, scratch `XDG_CONFIG_HOME`; no live matugen config exists):

```
matugen image ~/Pictures/berserk-wallpaper.jpg --json hex --dry-run -m dark -t scheme-vibrant --source-color-index 0 -q
```

`--source-color-index 0` is needed for unattended runs: per `matugen image --help`, without it 4.x may show an
interactive source-colour prompt. `-q` keeps the JSON as the only stdout. Saved to
`tests/fixtures/matugen-berserk.json`.

Top-level keys: `base16`, `colors`, `image`, `is_dark_mode`, `mode`, `palettes`.
- `primary`: **`.colors.primary.dark.color`** = `#ffb3af` (also `.colors.primary.default.color`
  = `#ffb3af`, `.colors.primary.light.color` = `#bf0022`)
- `tertiary`: **`.colors.tertiary.dark.color`** = `#fcb885` (`.default.color` = `#fcb885`,
  `.light.color` = `#865228`)
- Every role in `.colors` has the same `{dark,default,light}.color` shape
  (`surface`, `on_surface`, `primary_container`, `outline`, ...). Tonal palettes are at
  `.palettes.<name>.<tone>.color` (e.g. `.palettes.primary.80.color` = `#ffb3af`).
- `.image` holds the absolute wallpaper path.

## Spike e: Quickshell

Working command lines (inside the rig, i.e. via `tests/rig/run.sh`, which sets
`WAYLAND_DISPLAY`, `QT_QPA_PLATFORM=wayland` and the testbin paths):

```
tests/rig/run.sh qs -p tests/rig/qs-smoke.qml --no-color &      # run a config by path
tests/rig/run.sh qs list --all                                   # instances (id, pid, display)
tests/rig/run.sh qs log -p tests/rig/qs-smoke.qml -t 20 --no-color
tests/rig/run.sh qs ipc -p tests/rig/qs-smoke.qml show           # targets/functions
tests/rig/run.sh qs ipc -p tests/rig/qs-smoke.qml call rig ping  # -> pong
tests/rig/run.sh qs kill -p tests/rig/qs-smoke.qml               # -> Killed <id>
```

Instance selection flags for log/ipc/kill: `-p <path>` / `-c <name>`, `-i <id>`,
`--pid <pid>`, `-n` (newest). By default they only see instances on the same display
connection (`--any-display` to widen), which keeps rig and live separate. Logs live in
`/run/user/1000/quickshell/by-id/<id>/log.qslog`. A QML load error makes `qs` print
`ERROR: ... module "X" is not installed` and exit 255.

Smoke run (verified): `qs-smoke.qml` put one `PanelWindow` on each output
(`hyprctl layers`: namespace `quickshell` on DP-1 and eDP-1, 1920x64); both screenshots
show `RIG SMOKE DP-1 | hypr monitors=2 workspaces=2 focused=DP-1` (and `... eDP-1 ...`)
in green on dark grey. **`Quickshell.Hyprland` reflects the nested instance**:
`Hyprland.monitors` = `DP-1,eDP-1`, two workspaces, focused monitor DP-1 (it follows
`HYPRLAND_INSTANCE_SIGNATURE`).

Module imports (`tests/rig/qs-imports.sh`, each also touches a type): all OK -
`Quickshell.Hyprland`, `Quickshell.Bluetooth`, `Quickshell.Services.Notifications`,
`Quickshell.Services.Mpris`, `Quickshell.Services.Pipewire`, `Quickshell.Services.UPower`,
`Quickshell.Wayland` (`ScreencopyView`), `QtQuick.Shapes`, `Qt.labs.folderlistmodel`.
None failed. Harmless warning on every start: `qt.qpa.services: Failed to register with
host portal ... App info not found for 'org.quickshell'`.

Screencopy: grim captures the nested headless outputs (wlr-screencopy), and a
`ScreencopyView { captureSource: <eDP-1 screen> }` in a PanelWindow on DP-1 reached
`hasContent=true size=QSize(1920, 1080)` and rendered eDP-1's content in the DP-1
screenshot. So ScreencopyView works in the rig.

Rig caveats for service modules: the rig shares the live D-Bus session/system buses,
the live PipeWire (same `XDG_RUNTIME_DIR`), BlueZ and UPower. Reading is fine; a test
that instantiates `NotificationServer` would compete with the live mako for
`org.freedesktop.Notifications`, and Pipewire/Bluetooth/Mpris writes change the real
machine. Later units should not do either in the rig (or run qs under a private
`dbus-run-session`).
